# L10N — Tradução futura para Português (Brasil)

**Intenção do usuário**: adicionar **uma opção a mais** de idioma (PT-BR) no jogo, **sem substituir** os
idiomas existentes (EN, FR, DE, ES/SP).

## Evidências coletadas (2026-10-21, análise estática do ELF/disco — nenhuma hipótese sem base)

1. **O motor suporta 9 idiomas** (tabela em `../core/vilanguage.cpp`, motor Snowblind "VI"):
   `us, uk, fr, de, it, nl, pt, sp, en` — **`pt` já está na tabela**, com
   `GetIsoCode__10VILanguage12VILanguageID` mapeando ID → código ISO de 2 letras.
2. **O disco (USA) embarca apenas 4 pacotes de texto**:
   - `BG/DATA/SEL_EN.LMP`, `SEL_FR.LMP`, `SEL_GE.LMP`
   - `BG/DATA/GTEXT_DE.LMP`, `GTEXT_FR.LMP`, `GTEXT_GE.LMP`, `GTEXT_SP.LMP`
   - `LANGMENU.LMP` (menu de idiomas)
3. **O menu do jogo lista 4 nomes** (strings no ELF): `English`, `Deutsch`, `Español`, `Français`.
   Português **não** aparece no menu da versão USA.
4. **Convenção de nomes** (strings no ELF): `%s.lmp`, `%s.vif`, `%s.tex` — o código do idioma entra no
   nome: `SEL_<código>.LMP` / `GTEXT_<código>.LMP`.
5. **Português NÃO existe no disco** — teria de ser **criado** (traduzido).
6. **Fontes**: `DATA/*.ESF` (ARIAL.ESF, UI.ESF...) + `NETGUI/EUROPEAN.PF` (fonte européia usada por
   FR/DE/ES, que cobre a maioria dos acentos). **Verificar ã/õ** quando o jogo renderar (M3).

## Formato dos pacotes (estado atual da análise)
- `SEL_EN.LMP` (309 KB): cabeçalho de inteiros 32-bit LE + tabela de recursos: nomes de áudio `.vag`
  (vozes do menu!), texturas `.tex` — pacote de recursos do menu.
- `GTEXT_FR.LMP` (406 KB): cabeçalho próprio (`01.., 1c.., 80.., offset...`), um bloco `gtext.uni` e
  ~3.564 strings ASCII de 5+ — muitas parecem **códigos/índices** (`actin12ec`, `epilogued784`,
  `natasla6aca`...). Provável arquivo-texto compactado/indexado — **reversão completa pendente**
  (muito mais rápido com o jogo rodando + logs, M1/M2).

## Roteiro (após M1/M2; nada disto é pré-requisito do port)

1. **Reversão do formato** `GTEXT_*.LMP` / `SEL_*.LMP` (extrator + repacker), com o jogo rodando para
   comparar o que é carregado (log de IOP RPC/`%s.lmp`).
2. **Tradução** EN → PT-BR de todas as strings (ferramenta + revisão humana; projeto de fã).
3. **Empacotar** como `SEL_pt.LMP` + `GTEXT_pt.LMP` mantendo os arquivos EN/FR/DE/SP intactos
   (idiomas atuais **não** são tocados).
4. **Oferecer "Português (Brasil)" no menu**:
   - Hipótese A: se o menu lista os idiomas por existência dos pacotes, basta adicionar os arquivos.
   - Hipótese B (mais provável na versão USA): lista fixa de 4 → patch no port (mecanismo de hooks já
     existente, ex. `FunctionHooks`) ou extensão do texto do `LANGMENU`.
5. **Fonte**: garantir glifos ã/ç/õ (ajuste de `*.ESF`/`*.PF` se faltar — M3).
6. **Distribuição**: a tradução fica **fora** do repositório do port (conteúdo de jogo + tradução de
   texto comercial = zona cinzenta); apenas a **ferramenta** (extrator/tradutor) pode ser pública.

## Greek honesto
- O motor já sabe "pt" (bom!), mas o trabalho é de **fan-tradução completo**: reverter formato, traduzir
  milhares de strings, verificar fontes. Não é automático — são semanas de projeto dedicado depois de o
  jogo estar rodando.
